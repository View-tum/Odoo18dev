ลำดับนำเสนอ AMS สำหรับลูกค้า

ใช้หน้านี้เป็นหน้าเปิดจริงสำหรับ present ลูกค้า เป้าหมายคืออธิบายให้เข้าใจง่ายว่าเราช่วยลดงานซ้ำ ทำให้ flow ชัดขึ้น ใช้ Odoo standard ให้มากที่สุด และแยกจุดที่ต้องทำเพิ่มจริง ๆ

ข้อความหลัก: เราใช้ Odoo standard ก่อน แล้วทำเพิ่มเฉพาะจุดที่รูปแบบงานของ AMS ต้องการมากกว่า standard โดยเฉพาะงานที่กระทบ Stock, MRP และ Accounting ต้องยืนยัน rule ก่อน

ลำดับเปิดไฟล์จริง

ลำดับไฟล์ที่เปิดใช้พูดเรื่องอะไรคำพูดง่าย ๆ สำหรับลูกค้า
1 Dashboard
Excel แก้ไขได้		 สรุปว่าเราเข้ามาช่วยลดงานและจัด flow อย่างไร เราจะช่วยจัด requirement ให้เป็น flow เดียวกัน ลดงานซ้ำ และแยกให้ชัดว่าส่วนไหนใช้ Odoo ได้เลย ส่วนไหนต้องทำเพิ่ม
2 Manday และรายละเอียด Request อธิบาย Manday และ effort ที่ใช้ ตัวเลขนี้ใช้วางแผนและจัดลำดับงาน ยังไม่ใช่ราคาปิดสุดท้าย ต้องยืนยัน scope ก่อน
3 Mapping HTML
Excel แก้ไขได้
Draw.io แก้ไขได้		 Mapping ว่าแต่ละ request อยู่ flow ไหน อยู่ Odoo module ไหน ส่วนไหน standard และส่วนไหนต้องทำเพิ่ม/custom 44 ข้อคือ request จริง ส่วน 24 จุดเป็นข้อมูลประกอบจาก blueprint/note เพื่อให้ flow ครบ แล้วแยก module, standard และ custom ให้เห็นชัด
4 Workflow / Business Flow เปิด diagram ไล่ตั้งแต่ขาย ซื้อ คลัง ผลิต คุณภาพ ส่งของ จนถึงบัญชี เราจะไล่ flow จากต้นจนจบ เพื่อดูว่าใครทำอะไร เอกสารไหนเกิดตรงไหน และจุดไหนต้องตัดสินใจร่วมกัน
5 ปิดการนำเสนอ
Excel แก้ไขได้		 สรุปสิ่งที่ต้องยืนยันกับลูกค้าและรายการที่ต้องขอเพิ่ม หลังจากวันนี้เราจะขอ confirm scope, ตัวอย่างเอกสาร, format รายงาน และไฟล์/API ที่ต้องเชื่อม

  • 01_Dashboard_AMS_เราช่วยอะไร.xlsx - แก้ Dashboard
  • 02_Manday_และ_รายละเอียด_Request.xlsx - แก้ Manday และรายละเอียด request

  • 03A_Mapping_Standard_Custom_By_Flow.drawio - แก้ภาพ Module / Standard / Custom ราย flow
  • 04_Workflow_Business_Flow_AMS.drawio - แก้ workflow/business flow
  • 05_สรุปปิดการนำเสนอ_และ_Action_Next.xlsx - แก้สรุปปิด meeting และ next step

คำอธิบายตัวเลข 44 และ 24

  • 44 Customer Requests คือ request จริงจากไฟล์ R001 ของลูกค้า
  • 24 Supporting Mapping Points คือจุดเสริมจาก solution note และรูป blueprint ไม่ใช่ request เพิ่มใหม่
