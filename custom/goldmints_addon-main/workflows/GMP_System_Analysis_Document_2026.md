## 📌 1. วัตถุประสงค์การอัปเดต (2026)
เอกสารฉบับนี้เป็นการสรุปสถานะการตั้งค่าระบบ **To-Be (สภาพปัจจุบันที่ใช้งานจริง)** เพื่อทดแทนรายงานปัญหาช่องว่างระบบ (Gap Analysis) ในช่วงปี 2025 โดยมุ่งเน้นการขมวดรวมฟังก์ชัน Custom และ **Database Views** ที่ถูกสร้างขึ้นมาเพื่อตอบโจทย์ Report วิเคราะห์เชิงลึก

## 📌 2. สรุปการปิดช่องว่างระบบ (Gap Resolution - To-Be)

### 🔵 **ฝ่ายขาย (Sales)**
*   **จากปัญหา (2025)**: เช็คเครดิตล่าช้า, การออกรายงานยอดขายผ่านระบบทำได้ยาก
*   **สถานะปัจจุบัน**:
    *   ใช้งานระบบ **Credit Limit Check (`sale_credit_limit_warning`)** ดักห้าม Approve หากยอดรวมหนี้ + เช็คที่ยังไม่ได้เคลียร์ริ่งเกินวงเงิน
    *   ระบบ **Import SO Excel** ช่วยลดภาระการคีย์มือใบสั่งขายปริมาณมากจากห้างใหญ่

### 🟢 **ฝ่ายผลิต (Manufacturing)**
*   **จากปัญหา (2025)**: คีย์รายงานใบผลิตลงเอกสารหรือเอ็กเซล, ตัดต้นทุนพลาสติกเศษไม่ได้
*   **สถานะปัจจุบัน**:
    *   พนักงานสั่งงานผ่าน **Parallel Console UI** (Start / คีย์ยอด Done รายช็อต) สต๊อกตัดไหลลื่น
    *   ฟังก์ชัน **Scrap Landed Cost** ทบเศษขยะเม็ดพลาสติกกลับเข้าคำนวณต้นทุนสินค้าสำเร็จรูปจริงอย่างสมเหตุสมผล

### 🟡 **คลังสินค้าและจัดส่ง (Inventory)**
*   **จากปัญหา (2025)**: ตรวจเช็คสต๊อกดักยอดติดลบล่าช้า, วินิจฉัย Lot ยุ่งยาก
*   **สถานะปัจจุบัน**:
    *   เดินฟังก์ชัน **`stock_no_negative`** ป้องกันระบบอนุญาตตัดเบิกของที่ไม่มีอยู่จริงเชิงกายภาพ
    *   ฟังก์ชัน **`nano_transfer_product_lot`** บังคับตรวจความถูกต้อง Lot Number ระหว่างการเคลื่อยย้ายภายในโรงงาน

## 📊 📌 3. รายละเอียด Database Views (SQL Views Custom)
เพื่อลดขั้นตอนการดึงข้อมูลออกไปทำ Excel ระบบได้รับการสร้าง **SQL Views** สำหรับออกรายงาน Real-time ดังนี้:

### 🗂 **1. View: `purchase_price_history` (ประวัติราคาจัดซื้อ)**
*   **โมดูลพ่วง**: `purchase_price_history`
*   **หน้าที่**: ดึงข้อมูลราคาซื้อจากใบสั่งซื้อ (PO) ในอดีตเพื่อเปรียบเทียบราคาปัจจุบัน
*   **การทำงาน SQL**:
    *   `JOIN` ตาราง `purchase_order_line` และ `purchase_order` ที่สถานะเป็น `'purchase'` หรือ `'done'`
    *   คำนวณราคาเฉลี่ยสัดส่วน (`AVG(price_unit)`) ราย Product แบบเรียลไทม์
*   **ประโยชน์**: แจ้งเตือนฝ่ายจัดซื้อทันทีบนหน้าจอสร้าง PR/PO ว่าราคาที่จัดซื้อ "สูงหรือต่ำกว่าราคาประวัติการณ์"

---

### 🗂 **2. View: `mrp_production_summary_line` (สรุปต้นทุนการผลิตเชิงลึก)**
*   **โมดูลพ่วง**: `mrp_production_summary`
*   **หน้าที่**: รวมศูนย์ค่าใช้จ่ายทุกมิติของใบสั่งผลิต (MO) แตกแจงต้นทุนวัตถุดิบ แรงงาน และแม่พิมพ์
*   **การทำงาน SQL**: ใช้คำสั่ง `UNION ALL` ดึงข้อมูลจากหลายถัง:
    *   **Finished Product**: ยอดผลิตเสร็จอิงจาก `stock_move`
    *   **Component Cost**: มูลค่าเบิกจ่ายอิงจาก `stock_valuation_layer`
    *   **Operation/Workcenter**: ค่าคิดชั่วโมงเครื่องจักร
    *   **Employee Labor**: ค่าแรงพนักงานที่คีย์ผ่าน console
    *   **Mold Cost**: ค่าดีดบำรุงรักษาแม่พิมพ์
*   **ประโยชน์**: บัญชีต้นทุนเห็นเอกสาร **Cost Overrun (ต้นทุนบานปลาย)** ตรวจสอบ Variance เศษส่วนของวัสดุที่แทงขยะทิ้ง (Scrap Allocation) ได้แบบ 360 องศา

---

### 🗂 **3. View: `cheque_analysis_report` (สรุปวิเคราะห์ทะเบียนเช็ค)**
*   **โมดูลพ่วง**: `cheque_management`
*   **หน้าที่**: รายงานแทร็กสถานะ เช็ครับ (Inbound) / เช็คจ่าย (Outbound) ล่วงหน้า
*   **การทำงาน SQL**:
    *   `JOIN` ตาราง `cheque_inbound_outbound` และ `cheque_payment_detail_lines`
    *   กรวดสกัดวันที่สำคัญ: วันที่หน้าดิว (Due Date), วันเคลียร์ริ่ง (Clearing Date) และสถานะ (`Confirmed / Return / Paid`)
*   **ประโยชน์**: บัญชีสามารถกดดู Cash Flow กระแสเงินสดจากการพิจารณาใบเช็คที่ "รอวัน Clearing" ป้องกันยอดเครดิตพาร์ตเนอร์ลูกข่ายบวมเกินความเป็นจริง
